# Phase 3: التشغيل الأساسي (Core Operations)

---

## 3.1 سياسة التشغيل اليومية (Daily Workflow)

### قواعد العمل الأساسية
* ❌ **لا يمكن تسجيل أي عملية بيع دون وجود وردية نشطة مفتوحة**
* 🔐 **فتح الوردية يتم يدويًا من صاحب المطعم (Admin)**
* ⚠️ **في حال محاولة البيع دون وردية، يظهر تنبيه إجباري**

### تدفق العمل اليومي
```
1. Admin يفتح الوردية (صباحية/مسائية)
   ↓
2. الكاشير يستطيع تسجيل المبيعات
   ↓
3. نهاية الوردية: Admin يغلق الوردية
   ↓
4. احتساب الفروقات (إن وجدت)
```

---

## 3.2 إدارة الورديات (Shift Management)

### أنواع الورديات
* **وردية صباحية** (Morning Shift)
* **وردية مسائية** (Evening Shift)

### قواعد الورديات
* ✅ وردية واحدة نشطة فقط في نفس الوقت
* ✅ تسجيل وقت الفتح تلقائيًا عند الفتح
* ✅ تسجيل وقت الإغلاق تلقائيًا عند الإغلاق
* ✅ ربط جميع العمليات (مبيعات، مصاريف، مشتريات) بالوردية النشطة

## 3.3 إدارة الطاولات (Table Management)

### متطلبات الطاولات
* **تعريف أرقام الطاولات المتاحة في المطعم**
* **إمكانية إضافة/تعديل/حذف الطاولات (Admin فقط)**
* **عرض حالة الطاولات: (متاحة / مشغولة)**
* **ربط كل طلب طاولة برقم طاولة محدد**
* **منع استخدام نفس الطاولة لأكثر من طلب مفتوح**

## 3.4 إدارة المبيعات (Sales Management)

### أنواع الطلبات
النظام يدعم 3 أنواع من الطلبات:

#### 1️⃣ طلب طاولة (Dine-in)
* مرتبط برقم طاولة داخل المطعم
* الطاولة تصبح "مشغولة" عند فتح الطلب
* الطاولة تعود "متاحة" عند إغلاق الطلب

#### 2️⃣ طلب سريع (Takeaway)
* زبون يأخذ طلبه مباشرة
* لا يحتاج رقم طاولة

#### 3️⃣ طلب خارجي (Delivery)
* توصيل خارج المطعم
* لا يحتاج رقم طاولة

### قواعد المبيعات
* ✅ **إلزامية اختيار نوع الطلب قبل البدء**
* ✅ **عرض رقم الطاولة أو نوع الطلب في تفاصيل الفاتورة**
* ✅ احتساب الإجمالي تلقائيًا
* ✅ خصم أو عمولة ثابتة (مثل 5%)
* ❌ **لا يمكن تعديل أو حذف الطلب إلا بصلاحية Admin**
