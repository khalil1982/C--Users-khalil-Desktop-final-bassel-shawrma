## 4.1 الفروقات المالية (Cash Differences)

### آلية احتساب الفروقات
```
الرصيد المتوقع = (المبيعات النقدية) - (المصاريف) - (المشتريات)
الفرق = الرصيد الفعلي - الرصيد المتوقع
```

### تدفق إغلاق الوردية مع الفروقات
```
1. Admin يضغط "إغلاق الوردية"
   ↓
2. النظام يحسب الرصيد المتوقع تلقائيًا
   ↓
3. Admin يُدخل الرصيد الفعلي (النقد في الدرج)
   ↓
4. النظام يحسب الفرق آليًا
   ↓
5. إذا كان هناك فرق:
   → النظام يطلب "سبب الفرق" (إلزامي)
   → Admin يُدخل السبب
   → النظام يسجل الفرق في قاعدة البيانات
   ↓
6. الوردية تُغلق
```

* ❌ **لا يمكن إغلاق وردية بوجود فرق دون إدخال سبب**
* ✅ **جميع الفروقات تُسجَّل في جدول Cash_Differences**
* ✅ **الفروقات تظهر في التقارير المالية**
* ✅ **Admin يمكنه مراجعة سجل الفروقات في أي وقت**

## 4.2 سياسة انقطاع الكهرباء والأخطاء الحرجة

### الحماية من فقدان البيانات
* ✅ **جميع العمليات تحفظ فور إدخالها محليًا (SQLite)**
* ✅ **استخدام SQLite Transactions لضمان سلامة البيانات**
* ✅ **Auto-save كل 30 ثانية للطلبات المفتوحة**

### آلية الاسترجاع بعد الانقطاع
```
1. عند إعادة تشغيل التطبيق بعد انقطاع مفاجئ
   ↓
2. النظام يبحث عن طلبات غير مكتملة (status = "Draft")
   ↓
3. إذا وُجدت طلبات:
   → يظهر تنبيه: "يوجد طلب غير مكتمل"
   → خيارات: [استرجاع الطلب] أو [إلغاء الطلب]
   ↓
4. المستخدم يختار:
   → استرجاع: يُفتح الطلب في الشاشة الرئيسية
   → إلغاء: يُحذف الطلب من قاعدة البيانات
```

## 4.3 تصحيح الأخطاء (Audit & Adjustment)

### سياسة عدم التعديل المباشر
* ❌ **لا يُسمح بتعديل السجلات الأصلية في قاعدة البيانات**
* ✅ **يتم تصحيح أي خطأ عبر عملية تصحيح مستقلة (Adjustment)**
* ✅ **جميع عمليات التصحيح تُسجَّل في Audit Log**

### مثال على التصحيح
```
❌ خطأ: تم إدخال سعر خاطئ لصنف في طلب
✅ الحل: 
   1. إنشاء Adjustment Entry
   2. تسجيل القيمة القديمة والجديدة
   3. حفظ في Audit_Log
   4. تطبيق التصحيح
```

### جدول Audit_Log
```sql
log_id  | user_id | action      | table_name | record_id | old_value        | new_value        | timestamp
--------|---------|-------------|------------|-----------|------------------|------------------|-------------------
1       | 2       | UPDATE      | orders     | 45        | total: ₪100.00  | total: ₪95.00   | 2024-01-15 14:30
2       | 1       | DELETE      | products   | 12        | name: "قديم"     | NULL             | 2024-01-15 15:00
3       | 2       | ADJUSTMENT  | expenses   | 8         | amount: ₪50.00  | amount: ₪55.00  | 2024-01-15 16:45
```

## 4.5 التقارير (Reports)

### أنواع التقارير

#### 1️⃣ تقرير المبيعات
* إجمالي المبيعات
* عدد الطلبات
* متوسط قيمة الطلب
* **تقسيم حسب نوع الطلب:**
  * مبيعات الطاولات
  * مبيعات سريعة
  * طلبات خارجية

#### 2️⃣ تقرير الطاولات
* **الطاولات الأكثر استخدامًا**
* **معدل إشغال الطاولات**
* متوسط قيمة الطلب لكل طاولة

#### 3️⃣ تقرير الفروقات
* جميع الفروقات المالية
* أسباب الفروقات
* إجمالي الفروقات (إيجابية/سلبية)

#### 4️⃣ تقرير المصاريف والمشتريات
* إجمالي المصاريف
* إجمالي المشتريات
* تفاصيل كل عملية

### خيارات التصفية
* ✅ يومي (تقرير اليوم)
* ✅ حسب فترة زمنية (من → إلى)
* ✅ حسب الوردية (صباحية / مسائية)
* ✅ **حسب نوع الطلب (طاولة / سريع / خارجي)**
* ✅ **حسب رقم الطاولة**

### التصدير
* 📄 **PDF** (للطباعة)
* 📊 **Excel** (للتحليل)

## 4.6 المعايير المالية

### العملة والتنسيق
* **العملة:** الشيكل (₪)
* **رمز العملة الدولي:** ILS
* **التنسيق القياسي:** ₪123.45
* **دعم الحسابات حتى منزلتين عشريتين**
* **عرض رمز العملة في جميع الواجهات والتقارير**

### قواعد الحسابات
```
الإجمالي الفرعي = مجموع (السعر × الكمية) لكل صنف
الخصم = الإجمالي الفرعي × نسبة الخصم
الإجمالي النهائي = الإجمالي الفرعي - الخصم
```
